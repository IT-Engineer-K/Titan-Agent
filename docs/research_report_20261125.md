## 1. エグゼクティブサマリー（結論）

Titans（*Learning to Memorize at Test Time*, arXiv:2501.00663）の長期記憶モジュール **MAC（Memory as a Context）** を使い、基礎原理検証（ミニチュア実験フェーズ）を完了した。
目標は、新しいチャットを作らず 1 本道の超長期会話で育つパーソナル AI エージェントの実現である。
全 **6 本の実験（Exp 1 / 1.5 / 2 / 2.5 / 3 / 3.5）** を設計・実装し、Kaggle GPU（Tesla T4 16GB）で実測した。

1. **約 10M パラメータ級の超小型 Titans (MAC) でも、ツール使用・逆質問・長期記憶の再利用・記憶の上書きが機能する**
   - Exp 2.5（SFT 段階）では、学習時未見の超長距離（ディストラクタ 18 ターン / 約 608 トークン＝約 10 セグメント横断）でも **記憶再利用率 93.3%** を維持した。
   - 途中の前提変更に対しては、**上書き成功率 92%〜100%、古い値の誤用率 0%** を達成した。

2. **小型文字レベルモデルに対する素朴な GRPO（強化学習）の課題が明確になった**
   - SFT が天井に張り付く環境では、`skip(zero-var)` が多発して更新が空回りした（Exp 1.5 / Exp 2）。
   - 難易度を上げて更新率 70% を確保しても（Exp 2.5）、記憶能力自体は維持された一方で精度が退行した。
   - 退行の主因は、高めの学習率・文字レベルサンプリング（`temperature=1.0`）・緩いフォーマット罰則・タスク比率の偏りによる出力フォーマット崩壊と逆質問バイアスだった。

3. **Exp 3 / Exp 3.5 で「思考（CoT）と長期記憶ストリームの関係」に明確な結論が出た**
   - Exp 3.5 では、2 段階 SFT（フォーマット先行習得 → 短〜超長混合カリキュラム）を導入した。
   - その結果、**`turn_cot`（従来ターン型）と `stream_token_cot`（毎トークン残留型）の両方が、未見 `d=28`・6 ターン連続（最終長 438〜462 トークン）まで全項目で正解率 1.000・`stale = 0.000`** を達成した。
   - 一方、**`ephemeral_token_cot`（毎トークン揮発型）** はストリーム長を **約半分（228 トークン）** に圧縮できた。
   - しかし、途中ターンでの「記憶リハーサル効果」が失われるため、6 ターン目（`T6 = 0.240`, `stale = 0.16`）で精度が急落した。
   - **実用設計への結論**: 精度は `turn_cot` と `stream_token_cot` で同等（満点）だったため、速度とトークン長に優れる **ターン単位 CoT（重要前提のリハーサル込み）** を基本とする。超長期になった場合のみ、古い思考ログを圧縮・間引きする構成が最適である。

## 3. 各実験の定量結果と判断根拠

### 3-1. Exp 1.5（段階的カリキュラム学習：`exp1_curriculum_rl`）

- **環境**: Kaggle 無料枠 GPU（T4 16GB）、Titans (MAC) `tiny` プリセット。
- **Stage 1 (SFT)**: `loss` は `5.4167 → 0.0002` まで低下した。全レベルで `format_rate = 1.0` を達成した。
  - Level 1（1 段検索）: 正解率 **100%**（15/15）。
  - Level 2（2 段連鎖検索）: 正解率 **86.7%**（13/15）。
  - Level 3（記憶の再利用）: 正解率 **93.3%**（14/15）、記憶再利用率 **93.3%**。
- **Stage 2 (GRPO)**: SFT 精度が高すぎて、グループ内報酬分散が 0（`skip(zero-var)`）になった。Level 2 は `0.867 → 0.733` と改善しなかった。

### 3-2. Exp 2（思考整理・壁打ち：`exp2_thinking_partner`）

- **環境**: Kaggle Tesla T4、`tiny`（約 10.19M パラメータ、語彙 314）。
- **結果比較（各レベル 40 問評価）**:

| 指標 | Stage 1 (SFT 450 step) | Stage 2 (GRPO 120 step) |
| :--- | :---: | :---: |
| Level 1（1 項目逆質問）accuracy | **1.000** | 0.975 |
| Level 2（2 項目連続逆質問）accuracy | **1.000** | **1.000** |
| Level 3（記憶再利用壁打ち）accuracy | **1.000** | 0.925 |
| Level 3 `memory_reuse_rate` | **1.000** | 0.925 |

- **知見**: 10M 規模の Titans (MAC) で「不足前提の特定 → 逆質問 → 記憶再利用 → 要約」ループが完全に成立した。
- 一方、SFT で天井に張り付いたため、GRPO 更新は 15/120 回に留まった。後半の KL 逸脱（`0.0256`）により精度が微劣化した。

### 3-3. Exp 2.5（長距離記憶・上書きストレス：`exp2_5_memory_stress`）

- **環境**: Kaggle Tesla T4、`tiny`（`seq_len=1024`, `segment_len=64`, 語彙 347）。
- **設計意図**: SFT は `d <= 8` の中距離で止めた。GRPO で未見長距離（`d=10..16`）・上書き（L3）・2 スロット同時保持＋上書き（L4）を強化する設計にした。
- **結果比較（SFT vs GRPO）**:

| ベンチマーク | 指標 | Stage 1 (SFT) | Stage 2 (GRPO) | 変化 |
| :--- | :--- | :---: | :---: | :---: |
| **L1_short_d2** (~248 tok) | accuracy / mem_reuse | 0.92 / 1.00 | 0.88 / 1.00 | -0.04 / ±0.00 |
| **L2_long_d12** (~470 tok) | accuracy / mem_reuse | **0.72** / 0.88 | 0.52 / **1.00** | -0.20 / +0.12 |
| **L3_overwrite_d8** (~408 tok) | accuracy / overwrite | **0.76** / 0.92 | 0.36 / 0.92 | -0.40 / ±0.00 |
| **L4_composite_d10** (~453 tok) | accuracy / overwrite | **0.96** / 1.00 | 0.84 / 0.96 | -0.12 / -0.04 |
| **距離カーブ d=2** (251 tok) | accuracy / mem_reuse | 0.867 / 1.000 | 0.933 / 1.000 | +0.066 / ±0.000 |
| **距離カーブ d=6** (340 tok) | accuracy / mem_reuse | 0.867 / 0.933 | 0.467 / 0.933 | -0.400 / ±0.000 |
| **距離カーブ d=12** (475 tok) | accuracy / mem_reuse | 0.533 / 0.933 | 0.467 / 1.000 | -0.066 / +0.067 |
| **距離カーブ d=18** (608 tok) | accuracy / mem_reuse | **0.600 / 0.933** | 0.200 / 0.867 | -0.400 / -0.066 |

- **ポジティブな発見**:
  - SFT のみで、未見の `d=18`（608 トークン＝約 10 セグメント横断）でも **`memory_reuse_rate = 0.933`** を維持した。
  - 記憶の上書き（L3 / L4）で `overwrite_rate = 0.92〜1.00` を達成した。古い値の誤用率 `stale_memory_rate` は `0.00` だった。
  - GRPO のスキップ問題は解消した（更新率 `56/80 = 70%`）。L2 の `memory_reuse_rate` は `0.88 → 1.00` へ上昇した。
- **GRPO 退行の原因分析**:
  1. **文字レベルサンプリング（`temp=1.0`）× 緩いフォーマット罰則**: トークン重複や `| |` 空パイプがある壊れた出力にも高報酬（例: `2.00`）が付いた。その結果、相対 Advantage で壊れた出力が強化された。
  2. **L4 偏重による逆質問バイアス**: GRPO 学習の 40% が L4（常に `<ask>目的</ask>` が正解）だった。そのため、L3 でも既知の `目的` を聞き直す癖が付いた（`ask_exact_rate: 0.96 → 0.76`）。
  3. **更新ノイズ過多**: 1 エピソード（`group_size=4`）ごとの即時更新に、高 LR（`4e-5`）と弱 KL（`0.04`）が重なった。結果として KL が `0.0476` まで跳ね上がった。

### 3-4. Exp 3（毎トークン CoT：`exp3_per_token_cot`）

- **問題意識**: 1 本道の長期記憶ストリームでは、1 トークンごとに思考 `<t>...</t>` を挟むとストリーム長が膨張する。Titans の Neural Memory が細かい思考ログで希釈されるかを検証した。
- **比較する 3 方式（同一問題・同一シード、意味単位語彙 87 × 5 段依存ルール推論）**:
  1. `turn_cot`（従来型）: ターン冒頭に `<think>...</think>` をまとめて出力し、そのまま残留させる。
  2. `stream_token_cot`（毎トークン・残留型）: 各出力トークン直前に `<t>...</t>` を出力し、すべて残留させる。
  3. `ephemeral_token_cot`（毎トークン・揮発型）: 各出力トークン直前に `<t>...</t>` を出力する。トークン確定後に思考を破棄し、クリーンな回答のみを Titans 記憶ストリームへ積む。
- **実測結果（Kaggle 完走）**:
  - `turn_cot`: `d4=1.000` / `d16=1.000` / `3T=1.000`（最終長 204.0、`stale=0.000`）。
  - `stream_token_cot`: `d4=1.000` / `d16=0.700`（未見長での型崩れ） / `3T=1.000`（最終長 216.0、`stale=0.000`）。
  - `ephemeral_token_cot`: `d4=1.000` / `d16=0.867` / `3T=0.844`（T1 `1.000` → T2 `0.867` → T3 `0.667`、最終長 **99.0**、`stale=0.033`）。

### 3-5. Exp 3.5（フォーマット先行習得＋長さ混合カリキュラム：`exp3_5_length_curriculum`）

- **環境**: Kaggle Tesla T4、`tiny`（10.07M パラメータ、`seq_len=1024`, `segment_len=32`, 語彙 87）。
- **改良内容**:
  - 2 段階 SFT を導入した。前半 25%（`S1_fmt`）で型とルールを習得させ、後半 75%（`S2_len`）で短〜超長を混合学習した。
  - `ephemeral` には後半ターン重み付けサンプリングを追加した。
  - 評価には、未見超長距離 `d28`・6 ターン連続 `6T`・`format_ok` 診断を追加した。
- **結果比較**:

| 方式 | `d4` | `d16` | `d28` (未見) | `3T` | `6T` 全体 | `6T` T6 | `6T` 型遵守 | `6T` 最終長 | `6T` 推論時間 | `stale` |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **`turn_cot`** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | 438.0 | **565.6s** | **0.000** |
| **`stream_token_cot`** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** | 462.0 | 608.3s | **0.000** |
| **`ephemeral_token_cot`** | **1.000** | 0.920 | 0.880 | 0.600 | 0.867 | 0.240 | 0.993 | **228.0** | 606.9s | 0.027 |

- **知見**:
  1. 2 段階 SFT により、`stream_token_cot` の未見長での型崩れは完全に解消された。`turn_cot` と並んで、全ベンチマーク **1.000**・`stale = 0.000` に到達した。
  2. `ephemeral_token_cot` は型遵守率 `0.993` と履歴長約半分（228）を達成した。しかし、途中ターンでの思考リハーサルがないため、`6T` の Turn 6 で `0.240`（`stale = 0.16`）へ急落した。
  3. 実用チャットでは、精度が同等の **`turn_cot`（重要前提のリハーサル込み）** が速度とトークン長のバランスで最良と判断した。超長期になったときのみ、古い思考ログを圧縮・間引きするハイブリッド方針を採用する。
